# Initial survey — Ben 10 Omniverse (BLUS31017)

Date: 2026-09-24. Offline measurement only; nothing lifted or booted yet.

## Binary

- `EBOOT.BIN`: disc SELF, program type 4 (APP), key revision 0x1C, 9 080 112 B.
- `EBOOT.ELF`: 9 077 680 B, ELF64 BE PPU, entry OPD `0x891650`, section headers stripped.
- Decrypted with `ps3recomp/tools/unself/ps3_unself` (APP support added this day);
  byte-identical to `rpcs3 --decrypt`.
- No `.sprx` on disc: all game code is in the EBOOT.
- 22 embedded SPU ELFs (GoW2 comparison pending).
- PARAM.SFO: TITLE_ID BLUS31017, APP_VER 01.00, PS3_SYSTEM_VER 04.25, languages
  eng/fre/ger/ita/rus/spa.

## Notable differences from GoW2

- **cellSail (40 imports, 0 wired):** the Sail movie player. GoW2 plays video
  through cellVdec directly; this game uses the high-level player. Largest gap.
- **SPURS job chains** (`cellSpursCreateJobChainWithAttribute`, event-flag
  LV2 queue detach): not used by GoW2.
- **sys heap** (`_sys_heap_create_heap/malloc/memalign/free`) and
  `sys_prx_register_library`, `sys_spu_image_close`: missing in sysPrxForUser.
- NP/network imports (sceNp, sceNp2, NetCtl, Commerce2): likely stub-able
  (offline play).
- Multi-platform licensed title (also on 360/Wii U): expect lighter, more
  generic SPU usage than a first-party Cell-native engine. Not yet verified.

## First PPU lift (same day)

```bash
python3 ../ps3recomp/tools/find_functions.py EBOOT.ELF --json -o functions.json
python3 ../ps3recomp/tools/ppu_lifter.py EBOOT.ELF --functions functions.json -o recomp_macos -j 8
```

(python3 >= 3.10 required: the tools use `int | None` annotations; macOS system 3.9 fails.)

- find_functions: 17 716 functions (14 379 `.opd` descriptors, every one a function start), 0.4 s.
  No Ghidra seeds yet (GoW2 used them to close recall gaps).
- Lifter: 36 s wall, rc=0. 18 582 functions after boundary recovery (+1 split, 40
  truncated bounds extended), 255 jump-table dispatchers (2 348 cases, +865 case
  funcs), 70 289 emitted functions in 22 chunks (~13 M lines, 827 MB), 0 fallback
  stubs, 2 790 unique call targets.
- `lift_todo_audit.py`: 0 instructions the lifter cannot translate. The 5 102
  `/* TODO: .word ... */` in the output are inline jump-table data after
  `ps3_indirect_call(ctx); return;` (dead code), consistent with the audit.
- Not compiled or booted yet. Next: build against the runtime (needs a game
  main/HLE table like `gow2_gen/`), SPU image extraction (22 embedded ELFs).

## First build and boot (same day)

`./build_macos.sh` (generic subset of the GoW2 build: lift chunks + runtime PPU +
generated NID table + `boot_macos.cpp` + link). 22 chunks at -O1 in ~4-5 min;
binary `boot_ben10`, 149 MB.

Engine defects found and fixed on the way (ps3recomp b7cd1a1e, 25ff8a51,
fbe3424c, 8e7c89b0):

1. Link: `ps3_type15_block_stomp` (GoW2-only hook called from `vm_write32_hot`)
   had no default -> weak no-op.
2. Hang before guest entry: function registry had 2^16 slots, this title has
   70 489 functions -> infinite probe. Now 2^18 + fatal on full.
3. CRT `abort()` at 0x578A90: import stubs were not in functions.json (no
   Ghidra seeds), every `bl` to a stub was lifted as a no-op, so
   `sys_lwmutex_create` returned garbage. find_functions now reads .lib.stub.
4. Game exit after opening `Configurations/0000000100000001.cfg`: it reads it
   with `cellFsAioRead` (unimplemented). cellFsAio* added (sync callback on the
   caller's context).
5. `cellGame*` hardcoded GoW2 (HDD, NPUA80491): now from PARAM.SFO (disc, BLUS31017).
6. SIGSEGV in `cellSysutilGetSystemParamInt` (libs/ writes through a guest
   address as a host pointer): BE-aware shims.

GoW2 non-regression: e435 lift relinked with the new engine, 40 s headless vs
the current `g2play`: same 52 142 functions, PARAM.SFO "hdd NPUA80491",
cellFsAioInit now resolved, same guard-message profile.

Headless run (`PS3_NO_RSX=1`, 30 s): CRT + TLS ok, 4 PPU threads, SPURS kernel
(5 workers), config read via AIO, GCM setup (tiles, gamma), **first
`SetFlipCommand`**, then the main thread polls with `sys_timer_usleep`
(func_002AEA20 -> func_000F7D38) forever.

## Next wall: SPURS job chains

Unresolved: `cellSpursCreateJobChainWithAttribute`, `_cellSpursJobChainAttributeInitialize`,
`cellSpursJobGuardInitialize`; `cellSpursRunJobChain` is a stub that executes
nothing. GoW2 never used job chains. Jobs are SPU binaries (22 embedded SPU
ELFs). Also unresolved but likely harmless: `cellSysmoduleInitialize`,
`sceNp2Init`, `cellSaveDataEnableOverlay`. Not yet proven that the poll loop
waits on the job chain (next step: confirm what the func_002AEA20 loop polls).

Known systemic engine gap: `libs/` HLE functions take host pointers; any
function with pointer out-params faults unless it has a ctx shim in
`runtime/ppu/ppu_sysprx.cpp` (GoW2 hit them one by one too).
